This milestone changes presentation and information architecture only. It does not reopen time/calendar, Bazi natal or target-flow calculation, Ziwei natal or Structural Runtime R1-R8, Combined Target-Flow Fusion R2, disputed-candidate policy, or any source-backed deterministic rule.

## Product problem closed by this milestone

The previous desktop Workbench exposed the released deterministic system as an engineering surface: a large source form, independent Ziwei/Bazi bundles, and many sidecar panels injected around the two charts. That structure was valid for field-closure and audit work, but it did not present the accumulated system as one coherent charting product.

The desktop product shell now composes the same released facts into four user-facing work areas:

1. **本命总览** — shared birth-time credential plus Ziwei and Bazi natal charts in one primary workspace.
2. **时运联动** — Ziwei temporal navigation, Bazi target-flow resolution, and explicit shared-target projection.
3. **融合视图** — Combined Target-Flow Fusion R2 as a first-class cross-system product surface.
4. **专业审计** — ManifestHash, resolved profiles, rule/algorithm lineage, Structural R6-R8, star placement provenance, palace-stem topology, Dignity provenance, and transformation provenance.

The base birth form is reorganized so ordinary birth inputs remain primary while location/time calibration and explicit Profile controls remain available under advanced sections. Existing element IDs and backend request contracts are preserved.

## Architectural rule

`product_shell_assets.py` is a presentation-only composition layer.

It must not:

- call chart APIs itself;
- recompute Ziwei, Bazi, shared-time, target-flow, or fusion facts;
- change any request payload generated by released sidecars;
- select a disputed candidate winner;
- infer Ziwei outward/inward self-transformation direction;
- hide integrity failures.

It may move existing DOM panels, mirror visible statuses, change headings, group advanced controls, and provide view navigation.

This is deliberate. Deterministic facts continue to be produced by the existing services and sidecars; the shell only changes how those released facts are organized for the user.

## Compatibility

The shell preserves the established IDs used by browser regression tests and sidecar scripts. Existing exported JSON, hashes, server endpoints, loopback-only policy, and desktop launcher behavior remain unchanged.

The product shell is injected last in the Workbench asset chain so all released sidecar mount points exist before it composes them into the four product views.

## Remaining desktop work

This milestone is the first desktop productization closure, not the final Windows release acceptance. Remaining work is limited to product/distribution concerns, principally:

- calibration of the new shell on a real Windows display and browser;
- density and responsive tuning after real-machine visual inspection;
- two-version updater activation and rollback acceptance;
- final release packaging/version promotion once the productized shell is accepted.

None of those items is evidence that the deterministic chart engine is incomplete.
