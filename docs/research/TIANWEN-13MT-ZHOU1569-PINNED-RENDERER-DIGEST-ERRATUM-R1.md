# 天问 13MT｜固定 PyMuPDF 版本的原始页图 SHA 复现：13MQ/13MS 差异结案

**本批结论：13MQ 与 13MS 同一周相卷六 PDF 的两份 RGB 裁图 SHA 不同，现已在同一 GitHub Runner、固定 Pillow 11.3.0 的条件下，以 PyMuPDF 1.26.7 与 1.28.2 两个版本各自严格复现。差异归属为数字渲染版本，而非历史原印文本异文。**

## 1. 原始对象和实验控制

- 原始 PDF `https://www.kotenmon.com/cal/arabe/vol6.pdf`：**4,936,040 字节、45 页**，SHA-256 `4c006b7ce131902fe33012d42f62cd2bbc2140affa3d5886e0da02966352cb7c`。
- 同一 Actions [41197580583](https://github.com/chinaneedM/ziwei-bazi-model/actions/runs/41197580583) 先后安装 PyMuPDF **1.26.7**、**1.28.2**；均使用 Python 3.12.15、Pillow **11.3.0**、PDF 第15页、2.5× RGB、无 alpha、`[1295,70,1353,1370]` 同一裁图坐标。两次下载都重核 PDF 字节 SHA，无 OCR。
- 该 run **success**，两次 source-page RGB 与 crop RGB 都通过各自精确 SHA 断言；运行产物 artifact **13041700130**。
- 永久归档：13MS 原始 PDF + 页图 + 六 ROI `libfile_5c8aab97ac8c8191a721705a863c95f1`；13MT 双渲染配置报告 `libfile_51375c053958819190bdab1e980f6ebf`。GitHub artifact 自身为 30 天保留，永久源证不依赖其存续。

差异在仅切换 PyMuPDF 版本、固定 Pillow 的实验中得到重现；它是 **PDF 渲染输出层**的问题。13MQ 的早期图像散列作为其特定渲染配置下的证据继续有效，但不能脱离渲染器版本以“通用原件像素哈希”作跨版本断言。后续验算必须使用指定版本或重新标识版本化 RGB 摘要。

## 2. 前向勘误与证据等级

13MS 曾将这一点标作 `UNRECONCILED_DERIVED_PIXEL_RGB_SHA`，原因是尚未锁定同一 Pillow 版本。本批补齐双版本严格重放，结案**只有派生像素哈希差异**，并且保留旧批记录以供追溯。原始 PDF SHA 完全相同、纸本照片对应的书目范围未发生变化。

**并未解决的另一问题**：周相第14页纵列标签与第15日各数栏是否已逐栏原印绑定；是否与 G893 `001a→002b` 同一位制、历元、字段；1569序文与1477计算年的日期分层；日本内阁文库 `子151-0003` 当前官方物品／影印／印次记录的具体对应。上述都不能凭像素哈希技术问题解决来代替历史校勘。

G893 六项跨原件历史赢家仍 **0/6**；根源登记 **765**、Matrix **222/222**、谱图 **252/238**、未决 **11**；排盘 **CLOSED**，算法重开 **0**。不增加历史人物谱系推断。
