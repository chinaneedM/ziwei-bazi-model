# 天问 13GI — 台湾国图政府开放书目 CSV 原件路径与可复跑检索门槛

## 本轮为什么改走此路

截至13GH，已经弄清 NCL 到馆阅览、既有数字影像授权和研究高清复制三条流程不同，但源件编号 `208 03130` 依然只是 Commons 镜像书目。继续阅读一般申请说明无法定位原书实物。

本轮找到台湾政府资料开放平台上**提供机构为国家图书馆**的[《古籍書目資料》数据集](https://data.gov.tw/dataset/6839)。该政府目录明确标示了 CSV 资源，链接至国图官方域名：

`https://rbook.ncl.edu.tw/NCLSearch/rbook.csv`

目录明列关键字段「正題名、書號、索書號、作者、版本」，具有比 Commons 文本更强的第一方书目性质。政府资源页面与实际 CSV 文件是**两个不同证据级别**：目前只确认官方可下载资源链接，**尚未成功读取该 CSV 内容，也未见其中确实收录 03130**。

## 实际探针与档案契约

`scripts/probe-tianwen-13gi-ncl-catalog.py` 是不登录、不使用个人资料、只对官网公开 CSV 发出请求的受限脚本；对应 GitHub Actions `verify-tianwen-13gi-ncl-catalog-csv` 在当前分支 push 后执行并归档 `tianwen-13gi-ncl-official-catalog-probe`。探针计划记录 HTTP/下载访问边界、原字节 SHA-256、表头、总行数和「書號／索書號」精确 03130 命中记录（仅截取必要书目字段），不上传整份馆方 CSV。

本地容器的 NCL DNS 不可用，因此本地请求失败只属于**执行环境访问边界**，不得当作馆方记录不存在或数据集失效。工作流即使请求失败也应生成有错误原因的 JSON，可重试而不伪造肯定结果。

无论 CSV 是否命中，目录行只证「书目层级」，不能自动证明 Commons 的 `NCL-03130_09`、PDF第74/76页就是馆方特定实物的原正反叶，更不能判断清初旧钞或光绪补钞叶级年代。

## 继续保留的独立原文未决

- 旧数字第74页，第9、14日：**null**；第76页第30日：**null**。
- 1909 后印本第30日「四分九二二二」只属于**后印本**，不回填旧钞。
- 第5日 NLC「〇」／GK「五」、原字段「四分/初度/少/微」单位衔接、G893六组原本独立目标均未结。
- 本批不新增古籍图像、古代物理见证、历史原字、谱系节点边或确定性排盘算法修改。

**下一验证门槛**：读取探针产生的原始元数据报告。只有原 CSV 确切行与完整表头/哈希同在，才能更新第一方馆藏号绑定；由馆方详情页或获准原件图独立完成卷册和原叶交叉校验。
