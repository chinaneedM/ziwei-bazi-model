# 天问 13MX｜日本馆方正式书号冲突与全量 CI 简化修复

## 新增直接来源：公文书馆官方清单（不是摄影者转述）

日本国立公文书馆 2021 年 7 月官方公告「複製物の作成作業時期について」，附件「内閣文庫（漢籍）」[PDF 第 106/118 页](https://www.archives.go.jp/news/pdf/20210719.pdf#page=106)，清晰列出 **「子051－0003　回回暦法」**。它是原藏书号与书名的**馆方一手书目绑定**，属于计划制作复制物的清单；该文件不证明后续复制已完成、存在可下载影像、第六册内容、特定印次或原表数值。

先前 [2019 年摄影者索引](https://www.kotenmon.com/cal/arabe/Huihui_li.html) 则写 **「内閣文庫蔵『回回暦法』(子151-0003) 6冊」**，并附第六册「大統暦書」。摄影者的 151 与馆方官方 051 发生**实质书目号冲突**。本次仅确证馆方官方条目的 051 和摄影者自身标示的 151，**不能凭标题相同证明两个编号指向同一物理实物，也不能贸然宣称摄影者打错号码或馆方改号**。旧引文保留，正式查询先从 051 着手，须进一步绑定当前馆方 file/item、册次及第六册物理印次，再决定是否改写摄影本的对象身份。

## 前次完整 CI 失败的最小直接修复

远端 13MX HEAD 的 [clean-training-system 41202383178](https://github.com/chinaneedM/ziwei-bazi-model/actions/runs/41202383178) 最终失败：Full unittest 报告 6222 项运行中 errors=1，缺失 fitz。失败位置为导入 test_tianwen_13mt_zhou_render_profiles.py 时脚本顶层 import fitz；测试仅检查静态 SHA、渲染器指纹及裁剪几何，**并不实际打开 PDF**。

最小修复：将 fitz / Pillow 的 import 从脚本顶层移到 check(version) 实际渲染函数内。全量测试加载常量时不再强制依赖 PyMuPDF；执行固定渲染的专用工作流仍需按既有版本安装图像库。没有调整历史像素 SHA、渲染器预期、原始 PDF、排盘算法或添加冗余工作流。修复是否成功须以**本次新 HEAD 的实际 CI** 验证。
