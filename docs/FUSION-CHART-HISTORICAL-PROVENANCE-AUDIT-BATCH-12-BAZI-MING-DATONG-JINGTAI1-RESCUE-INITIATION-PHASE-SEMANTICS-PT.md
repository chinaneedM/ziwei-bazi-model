## 景泰元年“致失救護”与明初交食救护启动相位

Status: **RESCUE INITIAL-ONSET TRIGGER SOURCE-CLOSED / BARE 當在 LEXICAL PHASE STILL UNRESOLVED / CLOCK-ACQUISITION & LOCALITY OPEN / MD-G03 OPEN**

Batch 12PS established a philological firewall: the physical 1450 wording `月食當在卯正三刻` contains no explicit `初虧 / 食甚 / 復圓` lexeme, so `當在 -> 初虧` cannot be silently normalized. 12PT asks a different, operational question: does `致失救護` itself reveal which eclipse endpoint controlled the rescue start?

The early-Ming institutional `《諸司職掌》` answer is explicit. Solar/lunar eclipses are notified to the offices in advance. At the appointed time the Qintianjian officer reports `日初蝕`; only then do the officials enter the rescue/drumming sequence, which continues until the Qintianjian reports `復圓`. The lunar-eclipse rubric says `同前`.

The Zhengde `《明會典》` juan 95 transmission preserves the same structure as `報日初食 ... 報復圓`, with lunar rescue again `同前`. A 1464 Ming Shilu control separately uses `初虧` in eclipse forecast language and says a below-threshold eclipse is `例不救護`, showing that explicit onset terminology and rescue applicability coexist in the same institutional domain.

Adjudication: **the Ming rescue ritual's operational start endpoint is initial eclipse onset, not an arbitrary report time.** Consequently, the physical Jingtai-1 clause `欽天監官以為辰初初刻致失救護` source-binds the failed rescue schedule to the eclipse-onset endpoint.

The inference boundary remains strict. 12PT does not rewrite the literal 1450 `月食當在卯正三刻` into `初虧卯正三刻`; it does not prove direct visual observation; and it does not identify the observer, physical clock/clepsydra, apparent-vs-mean solar standard, or event locality.

Therefore Jingtai-1 remains **NOT_YET_ADMISSIBLE** as an absolute-time anchor. MD-G03 remains **OPEN_BLOCKING_GENERAL_ADAPTER**; HPA-DAYUN-CAL-002 remains **MISSING_FROM_PRODUCT**; runtime and modern meridian fitting remain fail-closed.
